# Base de datos — Fractales Academy V4

Modelo analizado: los seis SQL anteriores de `sql/`, `server/model.json`, consultas de la API y reglas de negocio. La referencia recibida y el esquema Azure comparten **25 tablas y 27 FK**. El archivo `00_REFERENCIA_SQL_SERVER_RECIBIDO.sql` contiene instrucciones de creación de una base y se conserva únicamente como referencia: **no forma parte de las migraciones**.

La estructura desplegada en Azure no se consultó. `00_DIAGNOSTICO_PREVIO.sql` permite compararla con el modelo local antes de autorizar cambios. Las migraciones rechazan nombres de base diferentes de `@BaseEsperada`, columnas, PK, FK o restricciones originales ausentes, y datos incompatibles. No asumen que contar 25 tablas sea suficiente.

También se crea `dbo.Seq_Operacion_V4`: secuencia `bigint`, incremento 1, sin ciclo, máximo de 18 dígitos. El backend forma códigos de 20 caracteres: prefijos `M4`, `P4`, `U4`, `N4`, `E4` y 18 dígitos. Se inicializa por encima de los códigos V4 que ya existan. La secuencia puede dejar huecos tras una transacción fallida; no debe reiniciarse para rellenarlos.

Resultado del modelo local: **29 tablas y 29 FK**, incluidas las dos tablas técnicas. Las 25 tablas originales y sus 27 FK permanecen. No se agregan columnas duplicadas de alumno, ciclo, grupo, deuda o nota.

## Decisiones para conservar datos

- Los teléfonos inválidos se muestran antes de la conversión. No se entrega una transformación automática de personas: cualquier corrección debe aprobarse y verificarse por separado, antes de capturar la línea base.
- `MATRICULA_INICIAL` y `MATERIALES` antiguos se conservan. Si un alumno tiene ambos, el diagnóstico lo muestra para revisión humana; no se presume que todos los materiales históricos sean el mismo cargo. V4 genera únicamente S/ 50 de inscripción para un alumno nuevo e impide añadir otro cargo inicial equivalente.
- Las mensualidades antiguas incompletas no se rellenan, los pagos anteriores no cambian de importe y las cuentas antiguas mantienen su nombre y hash. Un alumno legado sin matrícula previa tampoco recibe una inscripción retroactiva.
- Los triggers originales se conservan si existen y están activos; se instalan desde el SQL original cuando faltan. Los triggers nuevos son adicionales. El diagnóstico entrega las definiciones para revisar diferencias propias de Azure.
- Las correcciones de pagos y notas se registran en una misma transacción con la auditoría. Las intervenciones manuales de un DBA fuera de la aplicación deben documentarse por separado y respetar el procedimiento aprobado.

Consulta [GUIA_MIGRACION_AZURE_V4.md](GUIA_MIGRACION_AZURE_V4.md) para el orden, respaldo, mantenimiento y recuperación. No se aplicó ningún cambio sobre Azure.
